# 收编已有资料（抽取）

适用条件：机器上已有 agent 工具产生过资料。没有就跳过。

顺序不能倒：先收编，再接入。抽取是显式动作，可重复执行，靠“已抽取记录”跳过重复；抽取脚本按固定白名单读取，agent 不临场决定搬哪些文件，只负责抽取后询问分类。

## 白名单

只抽取这些：

| 来源 | 抽取内容 |
| --- | --- |
| codex | `memories/` 下的 Markdown、`rollout_summaries/` |
| codebuddy | `projects/*/memory/*.md` |
| workbuddy | `memory/*.md` |
| 三方工具 | `plans/` 下的 Markdown、附件、产物索引 |

明确排除：sqlite/jsonl 会话日志、缓存、blobs、登录态与凭据文件。设备上的 skill 副本不收编（见 SKILL.md 阶段 5）。

新增来源时给白名单加一行，同样受排除原则约束，不改执行规则。

## 执行规则

1. 只读抽取，不移动任何原物。
2. 结果落到 `000_Inbox/imported/<工具名>/<日期>/`，作为待判断区。
3. 列出抽取清单交人判断归属；人工确认后才分流进正式分区，未经判断不得进入正式分区。
4. 抽取后的副本是只读快照和候选素材，不构成权威，agent 不读取它。工作区内以根 `MEMORY.md` 与流水为准，工具自身的运行时仍以它自己的原生记忆为准，两者不合并、不互写。条目沉淀并记录来源与抽取日期后即与源记忆脱钩；两者冲突时以工作区为准，源侧冲突条目只标记待核对，不覆盖、不删除。未采纳的副本保留在 `imported/` 作为抽取证据。

## 幂等规则

抽取前先查 `000_Inbox/imported/<工具名>/` 下是否已有该来源的抽取目录。已有且内容非空时验证后跳过，不重复抽取。抽取目录本身就是已抽取记录，不另建记录文件。
