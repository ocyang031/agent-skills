# 日常规则

收口目录投入使用后的规则。部署时不执行本文件，部署后的会话以本文件为规则来源。

## 日常闭环

每次任务按四段执行，不新增决定，只把已有规则串起来：

| 段 | 动作 | 落点 | 结束判据 |
| --- | --- | --- | --- |
| 输入 | 新资料来自 `000_Inbox/010_Downloads/`、会话产生或抽取 | 判断归属后移入 `100_Works/<项目>/`、`200_Digital_assets/` 或 `050_Knowledge/Obsidian/`；未判断的留在 Inbox 并标记待判断 | 每条资料有明确归属，或明确标记待判断 |
| 输出 | 交付物与中间产物分开 | 交付物进 `100_Works/<项目>/`；可重建中间产物进 `.artifacts/` 并登记索引 | 产物有落点，`.artifacts` 有对应索引项 |
| 沉淀 | agent 写候选进草稿箱，用户分拣批准后提炼（见本文件记忆与账本一节） | 批准的进 `MEMORY.md`、知识库或 `.agents/rules/`；否决的删草稿并在流水记一笔 | 批准项带来源、适用范围、失效条件；否决项已删草稿并记流水 |
| 归档 | 项目结项 | 整个项目目录移入 `100_Works/_archive/<年份>/`，项目入口标记状态 | 目录已移入、入口已标记 |

指针落点：输入段记在 Inbox 的判断记录里；输出段记在项目目录的交付物条目或 `.artifacts/index.json` 的一条记录里；沉淀段记在 `MEMORY.md` 条目的来源字段或知识库、规则的对应条目里；归档段记在 `_archive/` 目录与项目入口的状态标记里。草稿的去向（批准、否决、暂缓）记在当日流水里。

自检时只提醒两件事，不自动修复：查缺口（只有输入、既无输出也无沉淀的悬空项，只提醒，不判失败，因为沉淀须经用户分拣批准，未沉淀属正常状态）；查一致性（指针声明的去向不存在、状态相互矛盾、同一结论在 `MEMORY.md` 里重复）。人对提醒的处置只有两种：补齐缺失段的指针，或明确判定“该任务无需继续”并保留这个结论作为最终指针。

凡移动必核数：移动前后字节数与条目数一致才算完成，不一致即停报。移动用系统自带的可靠拷贝工具（Windows 用 robocopy，macOS/Linux 用 tar 或等效工具）。

自检节奏：每次任务结束做一次轻量核对（落点对、指针全、报草稿箱待分拣数量）；全面自检由用户触发，不设固定周期，全面自检列出超过 7 天未分拣的草稿。

## 产物归口表

| 产物类型 | 落点 | 说明 |
| --- | --- | --- |
| 项目交付物：报告、方案、验收记录、测试证据与报告 | `100_Works/<归属前缀>-<项目名>/` | 归属前缀表未定之前暂行只用项目名 |
| 可重建中间产物：草稿导出、dump、trace、生成的中间文件 | `.artifacts/<任务或项目>/<日期>-<用途>/`，并登记 `index.json` | 默认保留 14 天，`.keep` 豁免；索引只保留 `index.json`，不另维护 Markdown 镜像 |
| 无项目归属的独立资产：文档、图片、电子书、视频 | `200_Digital_assets/` 下按 `220_Docs/230_Picture/240_E-book/250_Videos/` 分 | 有明确归属的跟随对象存放，不因格式拆散 |
| 知识沉淀：笔记、主题页、治理材料 | 知识库（`050_Knowledge/Obsidian/`） | 遵守知识库内部的写作与回写规则 |
| 工具清单、安装说明、版本与重建步骤 | `300_Dev/` | 不放应用本体与真实凭据 |
| 外部代码仓库 | `400_Code/<仓库名>/` | 直接平铺，不设分组子目录；各自独立版本控制；git clone 与快照并存 |
| 平台托管的产物（在线页面、目标文档等） | 本体不动，在对应 `100_Works/<项目>/` 留指针文件 | 指针含名称、标识或链接、日期、状态；永不复制、移动平台托管目录 |
| 新输入资料、下载暂存 | `000_Inbox/010_Downloads/`，判断归属后分流 | 未判断的留 Inbox 并标待判断 |
| 项目入口文档 | 各项目目录内的 `README.md` | 固定字段：项目名、状态、关联仓库的 remote 地址、指向仓库与交付物的链接 |

项目入口文档是代码仓库与项目之间的唯一纽带：代码事实以仓库为准，项目过程资料保留在 `100_Works/`，入口文档链接至仓库并记录 remote。仓库本身不放项目过程资料。

## 记忆与账本

五层分工：

| 层 | 位置 | 写什么 | 写入方式 |
| --- | --- | --- | --- |
| 账本 | 根 `HANDOFF.md` | 一个当前任务、任务队列、堵塞 | 覆盖写，40 行以内 |
| 流水 | `.agents/memory/<工具名>/<日期>.md` | 当天做了什么 | 追加 |
| 草稿 | `.agents/drafts/<日期>-<主题>.md` | 待分拣的沉淀候选 | agent 自动写，用户分拣后晋升或丢弃 |
| 长期 | 根 `MEMORY.md` | 跨会话仍成立的结论 | 追加，带来源 |
| 缓存 | agent 工具自身的记忆目录 | 工具自行管理 | 首次落地时一次性抽取 |

判据：如果一条内容明天还成立，就不该留在账本；如果只在今天有意义，就不该进 `MEMORY.md`。

账本固定四段、40 行含标题与空行：首行元信息（时间、写入工具、当前任务名）、当前任务（目标与未完成，每条未完成带下一步）、任务队列（非当前任务一行一条：任务名、状态、下一步）、堵塞（所有任务的堵塞，没有就写“无”）。切换任务时，先把原当前任务连同下一步写回队列，再把新任务提为当前任务，不得同时写两个当前任务。新任务先入队列，开始动手才提为当前任务。任务完成或放弃时移出账本，结论记入当日流水，不在账本留空位。队列行数受 40 行总封顶约束，写不下时先处理（完成、放弃或记入流水后移出）再写，不得挤掉当前任务的内容。账本纳入版本控制，接受覆盖写带来的 diff 噪音，换取未完成项不丢。

提炼规则：会话结束追加流水，并把符合起草判据的候选写进草稿箱。起草判据两条：跨会话仍成立；跨项目适用或写清边界。同一结论被独立写出两次优先起草。固定排除：临时路径、一次性命令、七天内可能变化的状态。提炼进 `MEMORY.md`、知识库或规则，必须经用户分拣批准，分拣是唯一的晋升触发；批准时以分拣决定加流水来源作证据。用户否决的候选，删草稿并在流水记一笔，不再重复起草。

并发写靠结构规避：流水按工具分文件，`MEMORY.md` 只追加并标注来源与日期；发现重复只报告，不自动合并。

`.artifacts/index.json` 字段：目录、用途、生成命令、到期日。暂行由生成方在创建时写入。初始内容为 `[]`。

## 保留与清理

- `.artifacts/`：默认保留 14 天，放 `.keep` 的目录豁免；清理先列出待删项再执行，产物可重建所以不逐次确认，但必须先列出。
- `000_Inbox/010_Downloads/` 等下载暂存：定期清空。`imported/` 作为抽取证据例外保留，不随暂存区清空。
- 资产层用清单管理：相对路径、大小、sha256、存储位置；清单进根仓库（无根仓库时暂行放项目目录内）。拷贝后按清单校验哈希，不匹配即停报。
- 项目结项：整目录移入 `100_Works/_archive/<年份>/`，入口标记状态，不新建一级归档目录。

生成清单的命令示例（在收口目录根执行）：

```bash
find 200_Digital_assets 100_Works -type f -not -path "*/_archive/*" -exec sha256sum {} +
```

## 代码规则

只在新增或修改代码文件时生效，优先级固定：安全与授权 > 目标仓库本地 lint 与风格 > 通用代码规则 > 个人偏好。子仓的 lint 有 CI 兜底，通用规则只是默认值。

- 禁用写法只列可机检项：`any`（除非同行写明理由）、`var`、空 catch、提交残留的 `console.log`、隐式全局。命名与注释风格进建议段，不进禁用段。
- 函数 50 行是建议值，超出时在 JSDoc 写一句为何不拆，只对新增函数生效。JSDoc 只强制导出函数与公共 API，已由类型系统表达的类型不重复标注。
- 编码配置只作用于根仓库（见 templates.md），子仓各用自己的 lint 与格式配置。

## 规则层级

收口目录根 `AGENTS.md` 是唯一外层根；知识库内自带的规则文件定位为子目录级规则，只细化知识库内部，不得放宽外层。两份规则同时适用时：

1. 安全性从严：同一事项都有约束时取更严者；任何一层不得放宽敏感内容、删除确认与授权要求。
2. 路径就近解析：相对 `.agents/rules/` 一律相对“声明它的那份规则文件”解析，工作区级与知识库级互不覆盖、不跨层查找；`MEMORY.md` 与 `.agents/memory/` 只指工作区根。
3. 冲突不静默：出现真正无法并存的条目时停机并报给人，不自动挑一份。冲突项写入 `HANDOFF.md` 的“堵塞”段，由人裁定后把结论按 ADR 方案记入工作区内的 `900_ADR/`，agent 读到更新才继续该项写入；裁定前该条保持停止，其余工作不受影响。

知识库规则文件的自我定位修改（从“自称根”改为“子目录级规则，上级为收口目录根规则文件”）必须等根规则文件到位后一并执行，上级文件不存在时不得提前修改，否则会制造悬空引用。

## 禁止清单

- 不把真实凭据值写入工作区内的任何文件、日志、命令输出或 skill、脚本。
- 不把机器层（工具本体、应用、缓存）收进收口目录；不把应用本体放进 `300_Dev/`。
- 不擅自搬动已有知识库；不擅自改根目录名大小写；不重建已存在的骨架。
- 不给 `400_Code/`、`300_Dev/` 下的子目录加编号；不在 `400_Code/` 下建分组子目录。
- 不把代码仓库的构建产物、依赖缓存当作资产编入清单；不把项目过程资料写进仓库。
- 不把 agent 工具自身的记忆当作权威，不与工作区记忆合并、互写。
- 不自动合并重复结论，不静默解决规则冲突，不临场决定抽取范围。
- 不删除附件、原始记录或不可重建内容，除非已检查引用关系并取得用户明确确认。
- 不把 `imported/` 的副本当作记忆读取，不把未判断的抽取结果分流进正式分区。
- 不绕过用户分拣把草稿晋升进 `MEMORY.md`、知识库或规则；不把草稿当作记忆读取；已否决的候选不重复起草。
- 不把两个任务同时写成当前任务；不把已完成或已放弃的任务留在账本里。
